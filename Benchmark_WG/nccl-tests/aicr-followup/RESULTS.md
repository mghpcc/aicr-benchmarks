## Part 1 — direction isolation

In an RDMA write the **client** reads its local buffer and writes into the **server's** buffer. Putting GPU memory on only one side therefore isolates one direction of the GPU's PCIe traffic.

| Test | What it measures | GB/s per direction | Engaging (healthy) | AICR prior |
|---|---|---:|---:|---:|
| host_baseline | host↔host, unidirectional | **48.4** | 47.8 | 46.3 |
| read_from_gpu | **NIC reads from GPU** | **47.5** | — | — |
| write_into_gpu | **NIC writes into GPU** | **45.5** | — | — |
| gpu_both_uni | GPU↔GPU, unidirectional | **26.4** | 49.4 | 47.5 |
| gpu_both_bidir | **GPU↔GPU, bidirectional** | **27.0** | 48.7 | 27.2 |

**Read 47.5 vs write 45.5 GB/s — ratio 1.04×.**

> **Roughly symmetric.** Neither direction is individually broken, so read-completion credits are **not** the mechanism. The fault appears only when the two directions are concurrent, which points at a shared resource rather than a per-direction throttle.

## Part 2 — switch path contrast

`PIX`/`PXB` means the GPU and NIC sit under the same PCIe switch, so the transfer is switch-local peer-to-peer. `NODE` means the GPU reaches the NIC through the root complex instead, bypassing switch-local P2P. AICR's switch is a **Broadcom PEX890xx**; Engaging uses a Mellanox MT2910 bridge chain — the last structural difference between the clusters.

| Path | GB/s per direction |
|---|---:|
| PIX/PXB rail, GPU bidirectional (switch-local P2P) | **27.0** |
| NODE rail, GPU bidirectional (via root complex) | **39.0** |
| NODE rail, GPU unidirectional | **47.6** |
| NODE rail, host bidirectional | **48.3** |

**PIX 27.0 vs NODE 39.0 GB/s per direction — avoiding switch-local peer-to-peer is +45%.**

> **A gradient, and the switch is the largest single term.** Three paths on the same node, worst to best:
>
> | Path | GB/s/dir |
> |---|---:|
> | GPU↔NIC **through the switch's P2P routing** (PIX) | 27.0 |
> | GPU↔NIC **via the root complex** (NODE) | 39.0 |
> | host↔NIC, no GPU (NODE) | 48.3 |
>
> Routing the same GPU traffic around switch-local P2P recovers +45%, so the **Broadcom PEX890xx peer-to-peer path is the dominant contributor** and the leading fix target (switch firmware/configuration). But NODE at 39.0 is still short of the 48.3 host baseline, so a second, smaller GPU-side term remains — the switch is not the whole story.

## Part 3 — concurrency scaling

N GPU/NIC pairs driven bidirectionally at once. A flat per-pair rate means a per-port limit; a falling per-pair rate means a **shared switch resource** (credits, buffers) saturating — the classic PCIe-switch signature.

| Pairs | Mean per-pair (GB/s/dir) | Node total (GB/s/dir) |
|---:|---:|---:|
| 1 | 41.6 | 41.6 |
| 2 | 16.3 | 32.5 |

**Per-pair rate changes -61% going from 1 to 2 pairs.**

> **Shared resource saturating.** Per-pair bandwidth falls as pairs are added — strong corroboration that a switch-wide resource is the limit, not a per-link property.
