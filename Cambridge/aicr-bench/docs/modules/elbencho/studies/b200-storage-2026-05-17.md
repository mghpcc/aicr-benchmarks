# B200 Elbencho Storage Study

Purpose: summarize B200 Elbencho storage measurements for small-block,
small-file, metadata, and historical peak workloads.

## Overview

B200 measurements were collected for one-node `small-block`, `small-file`, and
`metadata` workloads. Later supplemental historical peak evidence adds 31-node
read/write points, closing the peak-cluster memo shape.

## Measurement Conditions

| Field | Value |
| --- | --- |
| Platform | B200 |
| Date | 2026-05-17 |
| Target root | `/scratch/csim/elbencho` |
| Submission policy | One storage benchmark job active at a time |
| One-node client placement | `b0002` for sweeps; `b0003` for confirmation repeats |
| Historical peak placement | 31-node rows on `b0001-b0031` |
| CPU allocation | 128 CPUs per task |
| Result type | Study result, with memo status `Met` by supplemental historical evidence |

## Scope

- The one-node small-block, small-file, and metadata rows cover the Benchmark 0
  workload families for the measured B200 client placement.
- The 31-node historical peak rows close the peak-cluster memo shape as
  supplemental evidence.
- Historical peak rows are single best observed points, not medians.
- Metadata rows are non-cache-neutral because no cache-drop helper was used.
- Elbencho records filesystem-observed benchmark behavior; GDS readiness is
  covered by the [GDS module](../../gds/).
